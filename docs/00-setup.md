# Как это устроено на проекте

Описание рабочего окружения, в котором выполнены все три задания: какие инструменты подключены, как вызываются skills и агенты и какие ограничения действуют.

## Инструменты

| Инструмент | Для чего используется | Где видно в заданиях |
| --- | --- | --- |
| **Claude Code** (в IDE) | Основная работа: чтение кода и логов, субагенты, skills, рулы из `.claude/` | Все три ветки |
| **Jira / Confluence** (коннектор) | Тикеты `SOLO-xxxx`: критерии приёмки для ревью, история задачи для сообщений разработчику, инцидент по CI | Задание 1 (раздел 7), задание 2 (SOLO-4939), задание 3 (SOLO-4018) |
| **Playwright MCP** | Воспроизведение предполагаемого дефекта приложения на живом стенде: навигация, снимок, консоль, сетевые запросы. Только чтение, без логина и изменения данных | Агент `test-failure-analyst` (задание 1) |

**Чего нет и как это обходится:**
- Коннектора к CodeBuild/GitHub Actions нет. Лог запуска копируется вручную, перед передачей в Claude из него убираются хосты, бакет и внутренние адреса. Сводка запуска сохраняется в `data/ci-run-summary.md`, и агенты работают с ней.
- Коннектора к Slack нет. Сообщения готовятся в Claude, проходят проверку `comms-fact-checker` и отправляются вручную.

## Состав `.claude/`

| Тип | Файл | Когда срабатывает |
| --- | --- | --- |
| Rule | `rules/ci-pipeline.md` | Автоматически при работе с `ci/**`, `buildspec.yml`, `docs/**/*ci*.md` |
| Rule | `rules/communication.md` | `docs/**/*comms*.md`, `*digest*.md` |
| Rule | `rules/code-review.md`, `cypress-ui.md`, `gherkin.md`, `api-tests.md` | Тесты и документы ревью |
| Skill | `skills/ci-failure-analysis` | «почему красная сборка», вставлен лог CI |
| Skill | `skills/daily-comms` | «составь сообщение / дайджест / апдейт» |
| Skill | `skills/aqa-pr-review` | «сделай ревью PR / diff тестов» |
| Agent | `agents/ci-log-analyst` | Разбор лога, только чтение, без запуска |
| Agent | `agents/test-failure-analyst` | Перезапуск упавшего спека, скриншоты, Playwright MCP |
| Agent | `agents/comms-fact-checker` | Сверка черновика сообщения с данными перед отправкой |
| Agent | `agents/test-reviewer` | Первый проход ревью тестов, только чтение |

Рулы задают конвенции и подгружаются по путям. Skill задаёт порядок работы (Research → Plan → Implement → Verify) и формат результата. Агент выполняет одну узкую проверку в отдельном контексте и не правит файлы. Финальное решение и правки остаются за инженером. Общие для проекта команды и структура описаны в `CLAUDE.md`.

В каждой ветке лежат только те файлы `.claude/`, которые относятся к её заданию.

## Флоу по ситуациям

```
красный CI      → skill ci-failure-analysis → ci-log-analyst (по логу)
                → локальный прогон спека, Network → правка в отдельной ветке → повторный прогон → инцидент в Jira
нужно сообщить  → skill daily-comms → черновики → comms-fact-checker → правки → отправка вручную
ревью тестов    → skill aqa-pr-review → test-reviewer → ручная проверка каждого замечания → комментарии в PR
```

## Модели и лимиты

- Дейли-апдейт, дайджест и переформулировки для PM: лёгкая и быстрая модель.
- Разбор логов, гипотезы по флейкам и ревью: более мощная модель.
- Большие логи не вставляются целиком в чат. Сначала из них делается сводка (`data/ci-run-summary.md`), агентам передаётся она и нужные фрагменты лога.

## Безопасность и данные

- В настройках Claude отключена память «искать и ссылаться на другие чаты», чтобы детали другого клиентского проекта не попадали в сообщения.
- В общие документы не попадают хосты, бакеты, ARN, имена секретов, имя организации, данные пользователей. Используются плейсхолдеры `<APP_HOST>`, `<SSO_HOST>`, `<BUCKET>`, `<ORG>`, `<SECRET_NAME>`.
- Изменения, сделанные с помощью ИИ, вносятся только через PR с пометкой `AI-assisted` в тексте коммита или PR. Прямых коммитов в основную ветку нет.

## Повторяющиеся паттерны

- Ошибка `expected to run against origin <APP_HOST> but the application is at origin <SSO_HOST>` в замоканных UI-тестах означает запрос без `cy.intercept`, на который реальный бэкенд ответил 401/403 (случай из задания 1: `/onboardings` → 403). Первым делом стоит открыть Network в `cypress open`, а не увеличивать таймаут.
- Тест, прошедший со 2-й попытки, остаётся зелёным в итогах. Его нужно отдельно выносить в дайджест как кандидата во flaky.
- Агент-ревьюер без рулов проекта даёт общие советы. С рулами и списком изменённых файлов он даёт замечания, привязанные к коду. Каждое замечание всё равно проверяется вручную.
